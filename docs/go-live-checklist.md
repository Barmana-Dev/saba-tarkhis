# چک‌لیست پیش از استفاده با مشتری واقعی

این پروژه از نظر فنی قابل استقرار است، اما سامانه **اطلاعات شخصی و مدارک تجاری مشتری** می‌گیرد.
موارد زیر کار مالک محصول/کارفرما است و کد به‌تنهایی آن‌ها را انجام نمی‌دهد.

## ۱) حقوقی و محتوا

- [x] متن **موقت** حریم خصوصی در `/privacy` نوشته شد (چه داده‌ای جمع می‌شود، دسترسی، نگهداری،
      امنیت، حقوق کاربر) در `apps/web/src/pages/Legal.tsx`.
- [x] **شرایط استفادهٔ موقت** در `/terms` نوشته شد (ماهیت خدمات، حساب کاربری، مدارک، محدودیت‌ها،
      مالکیت محتوا، تغییر شرایط).
- [ ] **جایگزینی و تأیید حقوقی** هر دو متن بالا با نسخهٔ نهایی کارفرما (مهلت نگهداری، مسیر حذف
      داده، اطلاعات تماس واقعی). هر دو صفحه با برچسب «نسخه موقت» نمایش داده می‌شوند.
- [ ] اطلاعات تماس واقعی (تلفن، ایمیل، آدرس، ساعات کاری) در پنل مدیریت → تنظیمات وارد شود؛
      مقادیر فعلی «نیازمند تأیید کارفرما» هستند.
- [ ] دامنه نهایی در `apps/web/public/sitemap.xml`، `robots.txt` و `canonical` جایگزین شود.
- [x] عکس‌های واقعی کارت‌های خدمات در `apps/web/public/images/photos/services` قرار گرفتند (یک
      عکس برای هر شش خدمت، از Unsplash و تحت Unsplash License؛ عکاس و لینک هر عکس در
      `photos/CREDITS.md`). هدر صفحه اول تصویرسازی برداری خودمان است و صفحه «درباره ما»
      به درخواست کارفرما بدون عکس است.
- [ ] در صورت جایگزینی عکس، فایل جدید را با همان نام (۱۲۰۰×۶۷۵، JPEG، زیر ۳۰۰KB) بگذارید،
      متن جایگزین فارسی را به‌روز کنید و `photos/CREDITS.md` را هم اصلاح کنید. عکس‌های دارای
      لوگوی برندهای دیگر یا چهرهٔ شناسایی‌پذیر برای استفادهٔ تجاری باید بازبینی شوند.
- [ ] اگر کسب‌وکار مشمول مقررات نگهداری داده/مجوز است، وضعیت انطباق با مشاور حقوقی بررسی شود.

## ۲) سیاست نگهداری و حذف مدارک

- [ ] مدت نگهداری مدارک تعیین شود (پیشنهاد: تا پایان پرونده + ۱ سال برای پیگیری).
- [ ] روش حذف مشخص شود: حذف رکورد در پنل مدیریت + حذف فایل از `UPLOAD_DIR` (فایل‌ها با
      مسیر `requests/<requestId>/<uuid>.<ext>` ذخیره می‌شوند، پس حذف پوشه همان پرونده کافی است).
- [ ] درخواست حذف داده توسط مشتری: مسیر و مسئول پاسخ‌گویی مشخص شود.
- [ ] دسترسی پشتیبان‌گیری/بازیابی فقط برای افراد مجاز و با ثبت لاگ باشد.

## ۳) بکاپ و تمرین بازیابی

- [ ] بکاپ روزانه دیتابیس و پوشه فایل‌ها طبق `docs/deployment.md` بخش ۸ فعال شده است.
- [ ] بکاپ **خارج از سرور** (S3/سرور دوم) و رمزنگاری‌شده است؛ کلید بکاپ فقط اجازه نوشتن دارد.
- [ ] **تمرین بازیابی انجام شده**: `pg_restore` روی دیتابیس جداگانه + بازگردانی snapshot فایل‌ها،
      و سپس یک ورود واقعی با داده بازیابی‌شده و باز کردن یک مدرک (دانلود ۲۰۰ و حجم درست).
- [ ] زمان تقریبی بازیابی (RTO) و میزان داده قابل‌ازدست‌رفتن (RPO) ثبت شده است.

## ۴) قابلیت‌های احراز هویت که هنوز پیاده نشده‌اند

این موارد در MVP **نیستند** و باید تصمیم بگیرید کدام‌یک برای شروع لازم است:

| قابلیت | وضعیت فعلی | پیشنهاد برای شروع |
| --- | --- | --- |
| بازیابی رمز عبور | نیست؛ مدیر باید رمز را از دیتابیس/`user:create` بازنشانی کند | پیاده‌سازی با لینک ایمیل یا کد پیامکی پیش از عرضه عمومی |
| تأیید شماره موبایل (OTP) | نیست؛ هر شماره‌ای با فرمت معتبر پذیرفته می‌شود | اختیاری؛ برای جلوگیری از ثبت‌نام با شماره دیگران لازم است |
| اطلاع‌رسانی پیامک/ایمیل | نیست؛ وضعیت‌ها فقط در پنل دیده می‌شوند | ابتدا ایمیل (ارزان‌تر)، سپس پیامک |
| ورود دومرحله‌ای مدیر | نیست | برای حساب مدیر در production پیشنهاد می‌شود |

## ۵) عملیات

- [ ] `APP_ORIGIN` دقیقاً دامنه HTTPS نهایی است و `COOKIE_SECURE=true`.
- [ ] `npm run scan:verify` در محیط استقرار اجرا و فایل EICAR تشخیص داده شده است (در کانتینر
      ساخته‌شده یک بار تأیید شد: `Eicar-Signature FOUND`؛ امضاها با `freshclam` به‌روز بوده‌اند).
- [ ] اجرای production روی **Node.js 24 LTS** تأیید شده است. بیلد/تست با Node 24 انجام شده است و
      `engines.node` روی `>=24` است؛ روی سرور `node -v` ثبت و یک اجرای `npm test` گرفته شود.
- [ ] نام دیتابیس تست به `_test` ختم می‌شود و `npm run db:reset` در production اجرا نمی‌شود
      (اسکریپت `scripts/guard-db.mjs` مانع می‌شود — ولی برای احتیاط روی سرور هم `NODE_ENV=production`
      تعیین شده باشد).
- [ ] حساب مدیر واقعی با رمز قوی ساخته شده و حساب‌های دمو (`09120000001`…) **حذف یا غیرفعال** شده‌اند.
- [ ] لاگ خطاها/ممیزی به یک مقصد پایدار (فایل چرخشی یا سرویس لاگ) فرستاده می‌شود.
- [ ] مانیتورینگ ساده: `GET /api/v1/health` با هشدار روی خطا، و فضای دیسک (مدارک).
