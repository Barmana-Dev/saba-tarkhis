# چک‌لیست بررسی مرورگر (Manual QA)

مسیرهای اصلی (ثبت‌نام/ورود، ثبت درخواست با مدرک، تغییر وضعیت توسط کارشناس) با Playwright
خودکار شده‌اند (بخش ۰). مواردی که تست خودکار ندارند (ریسپانسیو، صفحه‌کلید، حالت‌های خطا) در همین
چک‌لیست **تکرارپذیر** آمده‌اند و هر بار پیش از انتشار اجرا می‌شوند. مدت تقریبی: ۱۵ دقیقه.

## آماده‌سازی

```bash
# ۱) دیتابیس و داده نمونه
docker compose up -d db
cd apps/api && SEED_DEMO_PASSWORD="Demo-local-123" npm run db:reset

# ۲) وب و API
cd apps/web && npm run dev     # http://localhost:3000
cd apps/api && npm run dev     # http://localhost:4000
```

حساب‌های دمو (رمز همان `SEED_DEMO_PASSWORD`): `09120000001` (مدیر)، `09120000002` (کارشناس)،
`09120000003` / `09120000004` (مشتری).

## ۰) تست خودکار مرورگر

```bash
cd apps/web
npx playwright install chromium        # یک بار؛ اگر مرورگر سیستمی دارید: E2E_CHANNEL=chrome
npm run test:e2e                        # رمز پیش‌فرض کارشناس در تست: Demo@12345
```

- تست‌های مرورگر روی دیتابیس دورریز `saba_tarkhis_test` اجرا می‌شوند، نه دیتابیس توسعه:
  `e2e/global-setup.ts` پیش از اجرا schema را با `prisma db push` می‌سازد و با
  `SEED_DEMO_PASSWORD` (پیش‌فرض `Demo@12345`) seed می‌کند؛ پس حساب‌های تستی در دادهٔ کاری
  ساخته نمی‌شوند.
- برای استفاده از دیتابیس آماده: `E2E_SKIP_SEED=1` (به‌همراه `E2E_DATABASE_URL` اگر نام دیگری دارد).
- برای پورت‌های غیرپیش‌فرض: `E2E_API_URL` و `E2E_WEB_URL` را ست کنید (پروکسی Vite خودکار
  به همان API اشاره می‌کند).
- پوشه‌ها: `apps/web/e2e` — ۵ سناریو: ثبت‌نام/خروج/ورود مجدد، رد رمز نادرست، ثبت درخواست
  چهارمرحله‌ای با آپلود PDF و دریافت شناسه `ST-…`، الزامی بودن رضایت‌نامه، تغییر وضعیت پرونده
  توسط کارشناس (بدون `E2E_STAFF_PASSWORD` این تست رد می‌شود).
- تست‌ها API و Vite را خودکار بالا می‌آورند (سرور فعال دوباره استفاده می‌شود).
- خروجی خطا در `apps/web/test-results/` (اسکرین‌شات و trace) — در مخزن کامیت نمی‌شود.
- در شبکه‌ای که دانلود مرورگر مسدود است از `E2E_CHANNEL=chrome` یا `E2E_CHANNEL=msedge` استفاده کنید.

## ۱) ریسپانسیو (۳ عرض)

در DevTools → Device Toolbar هر عرض را باز کنید و این سه مورد را تیک بزنید:

| عرض | صفحات | معیار قبولی |
| --- | --- | --- |
| ۳۶۰px | `/`، `/services`، `/guide`، `/articles`، `/contact`، `/faq` | نوار افقی اسکرول وجود ندارد (`document.documentElement.scrollWidth <= innerWidth + 1`) و هیچ متنی بیرون کادر نیست |
| ۷۶۸px | همان صفحات + `/dashboard`، `/requests/new` | منوی همبرگری درست باز/بسته می‌شود و کارت‌ها دو ستونه/تک‌ستونه مرتب می‌شوند |
| ۱۴۴۰px | همان صفحات + `/admin` | منوی افقی کامل دیده می‌شود و محتوا در `max-w-7xl` وسط‌چین است |

بررسی سریع بدون ابزار دستی، در Console مرورگر:

```js
// در هر صفحه اجرا کنید؛ باید 0 برگردد
document.documentElement.scrollWidth - window.innerWidth;
```

## ۲) دسترس‌پذیری با صفحه‌کلید

1. `Tab` از ابتدای صفحه: ترتیب فوکوس منطقی است، حلقه فوکوس (outline) روی همه لینک/دکمه‌ها
   **دیده می‌شود** (نباید `outline: none` بدون جایگزین باشد).
2. فرم ثبت‌نام `/register`: با `Tab` تا دکمه ارسال بروید، `Enter` بزنید. خطاها باید:
   - با رنگ و آیکون (نه فقط رنگ) نمایش داده شوند،
   - و با صفحه‌خوان به ورودی مربوط وصل باشند (در Elements بررسی کنید: ورودی دارای
     `aria-invalid="true"` و `aria-describedby` به شناسه پیام خطا).
3. فرم تماس `/contact` و فرم ثبت درخواست `/requests/new`: همان بررسی را تکرار کنید.
4. `Escape` منوی موبایل را ببندد و فوکوس به دکمه منو برگردد.
5. کنتراست: در DevTools → Elements، رنگ متن‌های ریز راهنما را بررسی کنید؛ حداقل نسبت
   **4.5:1** برای متن معمولی. متن‌های `text-slate-600` روی پس‌زمینه روشن این شرط را دارند.

## ۳) مسیرهای کاربردی

1. ثبت‌نام مشتری جدید → ثبت درخواست ۴ مرحله‌ای با یک PDF → دریافت شناسه `ST-YYYY-NNNNNN`.
2. بارگذاری فایل بزرگ‌تر از ۵MB → پیام خطای فارسی و بدون ثبت درخواست.
3. ورود مدیر → تغییر وضعیت پرونده → مشاهده تاریخچه و ممیزی.
4. ورود مشتری دوم → تلاش برای باز کردن پرونده مشتری اول → صفحه ۴۰۴ (نه ۵۰۰ و نه نمایش داده).
5. خروج → دکمه «بازگشت به بالا» در گوشه راست بعد از اسکرول ظاهر می‌شود و نرم به بالا می‌برد.
6. بازکردن لینک دانلود مدرک در تب جدید → فایل با `Content-Disposition: attachment` دانلود می‌شود.

## ۴) حالت‌های خطا

1. API را متوقف کنید (`Ctrl+C` در ترمینال API) و فرم تماس را ارسال کنید → پیام NETWORK_ERROR فارسی.
2. نشست را در دیتابیس منقضی کنید (`update "Session" set "expiresAt" = now() - interval '1 hour';`)
   و صفحه را رفرش کنید → کاربر مهمان می‌شود، کوکی پاک می‌شود و فرم تماس کار می‌کند.

## گزارش

نتیجه هر بخش را در PR/گزارش تحویل با تاریخ و مرورگر (مثلاً Chrome 132، Firefox 134) ثبت کنید.
اگر موردی رد شد، همان‌جا به‌صورت issue ثبت شود؛ چک‌لیست بدون گزارش کامل، «قبول» محسوب نمی‌شود.
